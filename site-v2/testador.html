HTTP 400 quer dizer que a plataforma recusou o pedido. A mensagem, em inglês, pede que o estorno de boleto seja feito à mão.

Os quatro resultados e o que fazer

Passou

Todos os avisos esperados chegaram ao seu app, e a API confirma o mesmo status.

O que você faz: Nada. Siga para o próximo cenário.

Falhou

A API mostra que o fato aconteceu (por exemplo, o pedido foi pago), mas o aviso não chegou ao seu app em 10 minutos.

O que você faz: Veja se o seu app estava no ar e respondeu rápido. Confira o endereço de avisos cadastrado no painel. Depois rode python -m testador rejulgar: se o aviso chegou atrasado, o resultado muda.

Inconclusivo

A plataforma ainda não terminou de processar este pedido (por exemplo, o estorno está em análise). Então é normal o aviso ainda não ter chegado. Não é erro do seu app.

O que você faz: Espere e confira de novo com python -m testador rejulgar. Se continuar assim, pergunte à plataforma quanto tempo leva esse processamento.

Não executado

A plataforma recusou uma etapa do teste (por exemplo, não aceita estorno de boleto pela API). O seu app nem chegou a ser testado neste cenário.

O que você faz: Não é falha do seu app. Leia o motivo. Se o cenário for exigido, descubra com a plataforma como ele é feito (no caso do boleto, a própria API pede que o estorno seja feito à mão).
